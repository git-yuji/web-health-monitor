# Web Health Monitor

Webサイトの稼働状態を定期的に確認し、結果を記録するモニタリングツールです。

## 目標

単発のサイト診断だけでなく、時間による変化や異常に気づけるツールを目指します。

## MVPで実装する機能

- URLの登録
- HTTPステータスの確認
- 応答時間の計測
- SSL証明書の有効期限確認
- 診断結果の保存と履歴表示

## 将来追加したい機能

- DNS・メール設定の確認
- セキュリティヘッダーの確認
- 異常時の通知
- 複数サイトのダッシュボード

## 使用技術

- TypeScript
- Vite
- Tailwind CSS

バックエンドはNode.js標準のHTTPサーバー、保存にはローカルのJSON Linesファイルを使用します。

## セットアップ

```bash
nvm use
npm install
```

フロントエンドと診断APIを別々のターミナルで起動します。

```bash
npm run dev:api
```

```bash
npm run dev
```

診断に成功すると、結果は`data/check-results.jsonl`へ追記保存されます。
このファイルはローカルデータのためGitの管理対象には含まれません。
保存された最新20件は、画面の診断履歴に新しい順で表示されます。
最新の診断URLについては、保存された応答時間の推移もグラフで確認できます。

監視対象は`POST /api/targets`へ`{"url":"https://example.com/"}`を送ると登録でき、
`GET /api/targets`で登録順に取得できます。

## 定期監視（Phase 3）

診断APIを起動すると、登録済みURLを順番に診断します。最初の巡回は起動直後、
次の巡回は前回の完了から5分後です。巡回は重複せず、監視対象は毎回読み直すため、
追加したURLは次の巡回から対象になります。画面を閉じてもAPIが動いていれば監視を続けます。

間隔は環境変数で変更できます（単位はミリ秒、1000〜2147483647）。
`0`を指定すると定期監視を無効にできます。手動診断APIは引き続き使用できます。

```bash
MONITOR_INTERVAL_MS=60000 npm run dev:api
MONITOR_INTERVAL_MS=0 npm run dev:api
```

- 応答を取得できた診断結果は従来の`data/check-results.jsonl`へ保存します。
- 全巡回の判定と通信失敗は`data/monitor-events.jsonl`へ追記します。
- HTTP 200〜399以外、SSL検証エラー、SSL残日数30日以下を異常と判定します。
- タイムアウトやDNS・接続エラーも記録し、次のURLの診断を続けます。
- 異常と通信失敗はサーバーの標準エラー出力へ通知します。メール・Webhook通知と
  監視イベントの画面表示は今後の実装対象です。繰り返す異常は各巡回で出力します。
- 保存処理の失敗は運用エラーとして出力し、サイトの通信障害とは区別します。

監視はAPIの単一プロセスで実行してください。複数プロセス間の排他制御、ログの保存期間管理、
停止中の診断の補完はありません。SIGINT・SIGTERMでは次の巡回を停止し、実行中の診断と
保存処理の完了を待ちます。診断の応答待ちは最大10秒ですが、保存処理に時間制限はありません。
画面の履歴はページ再表示または手動診断後に更新され、稼働率は引き続き完成イメージです。
