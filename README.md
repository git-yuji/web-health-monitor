# Web Health Monitor

Webサイトの稼働状態を定期的に確認し、結果を記録するモニタリングツールです。

## 目標

単発のサイト診断だけでなく、時間による変化や異常に気づけるツールを目指します。

## MVPで実装する機能

- URLの登録
- HTTPステータスの確認
- 応答時間の計測
- SSL証明書の有効期限確認
- 診断結果の保存と履歴表示
- セキュリティヘッダーの確認

## 将来追加したい機能

- DNS・メール設定の確認
- 異常時の通知（サーバーログへの出力は実装済み）
- 複数サイトのダッシュボード

## 使用技術

- TypeScript
- Vite
- Tailwind CSS

バックエンドはNode.js標準のHTTPサーバー、保存にはローカルのJSON Linesファイルを使用します。

## セットアップ

```bash
nvm use
npm install
```

フロントエンドと診断APIを別々のターミナルで起動します。

```bash
npm run dev:api
```

```bash
npm run dev
```

診断に成功すると、結果は`data/check-results.jsonl`へ追記保存されます。
このファイルはローカルデータのためGitの管理対象には含まれません。
保存された最新20件は、画面の診断履歴に新しい順で表示されます。
最新の診断URLについては、保存された応答時間の推移もグラフで確認できます。

監視対象は`POST /api/targets`へ`{"url":"https://example.com/"}`を送ると登録でき、
`GET /api/targets`で登録順に取得できます。

## 定期監視（Phase 3）

診断APIを起動すると、登録済みURLを順番に診断します。最初の巡回は起動直後、
次の巡回は前回の完了から5分後です。巡回は重複せず、監視対象は毎回読み直すため、
追加したURLは次の巡回から対象になります。画面を閉じてもAPIが動いていれば監視を続けます。

間隔は環境変数で変更できます（単位はミリ秒、1000〜2147483647）。
`0`を指定すると定期監視を無効にできます。手動診断APIは引き続き使用できます。

```bash
MONITOR_INTERVAL_MS=60000 npm run dev:api
MONITOR_INTERVAL_MS=0 npm run dev:api
```

- 応答を取得できた診断結果は従来の`data/check-results.jsonl`へ保存します。
- 全巡回の判定と通信失敗は`data/monitor-events.jsonl`へ追記します。
- HTTP 200〜399以外、SSL検証エラー、SSL残日数30日以下を異常と判定します。
- タイムアウトやDNS・接続エラーも記録し、次のURLの診断を続けます。
- 異常と通信失敗はサーバーの標準エラー出力へ通知します。メール・Webhookなどの
  外部通知は実装していません。繰り返す異常は各巡回で出力します。
- 保存処理の失敗は運用エラーとして出力し、サイトの通信障害とは区別します。

監視はAPIの単一プロセスで実行してください。複数プロセス間の排他制御、ログの保存期間管理、
停止中の診断の補完はありません。SIGINT・SIGTERMでは次の巡回を停止し、実行中の診断と
保存処理の完了を待ちます。診断の応答待ちは最大10秒ですが、保存処理に時間制限はありません。
画面の履歴はページ再表示または手動診断後に更新され、稼働率は引き続き完成イメージです。

### 定期監視の履歴表示

「定期監視の履歴」で正常・異常・通信失敗の最新20件を追記順の逆順に表示します。
各イベントのURL、判定、理由、診断日時を確認できます。通信失敗もこの一覧に表示されます。
SSL残日数30日以下は定期監視で「異常」と判定するため、既存の診断履歴の「正常」とは
判定条件が異なります。

ページ表示時、表示中の30秒ごと、「履歴を更新」ボタンを押したとき、タブへ戻ったときに
更新します。更新に失敗した場合はエラーを表示し、取得済みの一覧を保持します。
監視未実行の場合は履歴がない旨を表示します。

`GET /api/monitor-events`で`{"events":[...]}`を取得できます。
保存ファイルがない場合は空配列を返し、取得範囲内の保存データが破損している場合は500を返します。
一覧は保存できた監視イベントを対象とするため、イベント保存に失敗した診断は表示されません。

## セキュリティヘッダーの確認

手動診断と定期診断で次の5項目を確認し、取得した値・判定・説明を保存します。
最新の診断結果は「セキュリティヘッダーの確認」に表示し、過去の結果は診断履歴の
同名の項目を開くと確認できます。導入前の履歴はヘッダー情報なしとして表示します。

| 項目 | 確認内容 |
| --- | --- |
| Strict-Transport-Security | HTTPS応答の正のmax-age。HTTPでは対象外、0や不正・重複値は要確認 |
| Content-Security-Policy | 適用するポリシーの有無。Report-Onlyのみ、広い許可、空の値などは要確認 |
| X-Content-Type-Options | nosniffの指定 |
| CSP frame-ancestors / X-Frame-Options | CSPによる制限を優先。なければDENY・SAMEORIGINを確認 |
| Referrer-Policy | 最後の対応ポリシーを確認。unsafe-urlなど送信範囲の広い値は要確認 |

判定は「設定済み」「未設定」「要確認」「対象外」です。設定済みは確認対象の設定を
検出したことを示し、安全性を保証するものではありません。未設定でもサイトの用途や
ブラウザの既定値によって影響が異なります。CSPの完全な構文検証や、実際のページ内容と
許可元の整合性の検証は行いません。複雑な設定は手動確認してください。

入力したURLの最初の応答のみを確認し、リダイレクト先は追跡しません。
HTMLのmetaタグは確認対象外です。ヘッダー判定は参考情報として表示し、既存の
HTTP・SSLによる正常判定や定期監視の異常判定には加算しません。
診断APIの`securityHeaders`に5項目の結果を返し、診断履歴にも保存します。
